# BASHCAT Dash — v3.1 效能優化

使用者實機回饋：FPS 偏低。現況已是局部刷新（`AVOID_TEAR_MODE=3`：PSRAM 雙 framebuffer + LVGL direct mode，只畫髒區域，再把髒區域複製到另一張 buffer）。以下是瓶頸分析與要做的事。

## 先釐清：FPS tile 量的是什麼
`monitor_cb` 只在 LVGL 真的重畫時觸發。畫面靜止時 FPS 本來就低，這不是效能問題。要能區分「沒東西要畫」與「畫不動」：
- FPS tile 改顯示兩個數字：`fps`（每秒重畫次數）與 `ms`（monitor_cb 的 `time_ms`，每幀繪製耗時，取 1 秒內最大值）
- 每 2 秒用 `ESP_LOGI("perf", ...)` 印出 fps、平均/最大 render ms、平均 flush 像素數，方便序列埠量測

## 1. 編譯與系統設定（`sdkconfig.defaults`）
| 設定 | 改成 | 理由 |
| --- | --- | --- |
| `CONFIG_COMPILER_OPTIMIZATION_PERF` | `y`（-O2） | 預設 -Og，LVGL 軟體繪圖差 20–40% |
| `CONFIG_LV_DISP_DEF_REFR_PERIOD` | `15` | 原本 30 ms → 最高 33 fps；面板 VSYNC 約 39 Hz（16 MHz / (816×496)），要讓 LVGL 每個 VSYNC 都趕得上 |
| `CONFIG_ESP32S3_DATA_CACHE_64KB` | `y` | 加大 data cache，降低 PSRAM 存取 |
| `CONFIG_ESP32S3_INSTRUCTION_CACHE_32KB` | `y` | |
| `CONFIG_SPIRAM_SPEED_120M` | **不要預設開**；在 NOTES 記錄為可選（實驗性，Octal PSRAM 120 MHz 頻寬 +50%，需 `CONFIG_IDF_EXPERIMENTAL_FEATURES=y`，已開） | 需實機穩定性驗證 |
| `CONFIG_EXAMPLE_LVGL_PORT_TASK_PRIORITY` | 維持 2 | |

## 2. 儀表重寫：最大的瓶頸
`lv_meter` 每次 `set_indicator_end_value` 都會 invalidate **整顆表**（主表 300×300 = 9 萬像素），然後重畫 51 條刻度、6 個數字、兩條帶遮罩抗鋸齒的弧。數值動畫每幀都觸發，三顆表一起動時每幀重畫 ~14 萬像素的高成本內容。

改法：
- **靜態層快取**：刻度、刻度數字、灰色軌道弧只畫一次。用 `lv_snapshot_take()`（LVGL 8.4 有，需 `CONFIG_LV_USE_SNAPSHOT=y`）把它們渲染成 `lv_img_dsc_t`（RGB565 + 若需要透明則 `LV_IMG_CF_TRUE_COLOR_ALPHA`，或直接畫在不透明 `#0B0D0F` 底上避免 alpha），然後刪掉原本的 meter，改放一張 `lv_img`。快取圖放 PSRAM。
- **數值弧改用 `lv_arc`**：LVGL 8 的 `lv_arc_set_value` / `lv_arc_set_angles` 只 invalidate **變動的角度區段**（`inv_arc_area`），不是整個物件。去掉 knob（`LV_PART_KNOB` 隱藏）、`LV_OBJ_FLAG_CLICKABLE` 交給外層、背景弧透明（軌道已在靜態圖）。
- 數字 label 放在固定寬度容器裡，文字改變只 invalidate label 區域。
- 顏色過渡改 `lv_obj_set_style_arc_color(arc, c, LV_PART_INDICATOR)`。
- 保留所有現有動畫行為（開機 sweep、re-sweep、收回再掃出、交換指標）與外觀，像素上要跟現在幾乎一樣（拿模擬器截圖比對）。

## 3. 其他重畫成本
- sparkline / tile 歷史圖：`lv_chart` 每加一點會 invalidate 整個 chart；chart 尺寸維持小即可，確認沒有在 sample 以外的時候 invalidate
- 狀態點呼吸動畫：只動 8×8 物件 OK
- 檢查所有 `lv_obj_set_style_opa` 的整物件透明度（會走 layer 渲染，成本高）：只允許出現在短暫的進場動畫，**動畫結束後必須把 opa 設回 `LV_OPA_COVER` 並移除 local style**（`lv_obj_remove_local_style_prop(obj, LV_STYLE_OPA, 0)`），否則之後每次重畫都走 layer
- 切頁滑動：滑動中每幀全螢幕重畫是無法避免的；把滑動時間維持 ≤300 ms，並在滑動時暫停數值動畫更新（sample 照取，只是不啟動 anim），減少同時髒區
- 待機頁淡入淡出若用全螢幕 opa，同上規則

## 4. 驗收
- `idf.py build` 零錯誤，`bash sim/build.sh` 截圖與優化前視覺一致（輸出 `sim/out/perf_compare_*.png` 前後對照）
- 模擬器中統計每幀 invalidate 的像素數，優化前後在 DASH 頁常態運作 10 秒的平均值，寫進 NOTES（例：「每幀平均重畫 142,000 px → 18,000 px」）
- 更新 `main/ui/NOTES.md` 的效能章節
